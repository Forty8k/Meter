METER MDark ANALYSER - HOW TO
===========================

What it does
  Runs every version of the ORIGINAL Airwindows Meter it knows (0.5.5, 0.5.6 ...) over a track, once, much faster than
  real time and with no DAW, and keeps what each one sees and grades in a library folder. Your own Meter tweaks play no
  part in it, so the data never goes out of date: any gauge, grade or hint can be worked out again later from the library.
  When Chris publishes a new Meter, a new analyser build with it appears automatically (see "Updates" below).

Using it
  1. Unzip and run "meterDARK Analyser.exe". (Windows may warn about an unknown publisher: More info > Run anyway.)
  2. Drag audio files or whole folders onto the window, or use "Add files...".
     WAV, AIFF and FLAC are best (lossless). Ogg and MP3 also work but are marked as lossy.
  3. Each track gets one line in the log, with what the original meter reads for it.
  4. "Open library folder" shows the results. The default library is Documents\meterDARK Library (an existing "meterDARK Library" folder keeps being used).
     "Change library folder..." picks another (for example on a bigger drive).

  Adding the same file again is skipped (it is recognised by its content, not its name).
  A file scanned by an older version of the analyser is scanned again and updated in place; your own values are kept.
  You can keep adding tracks whenever you like; the library just grows.

The Library tab
  Every track in the library, one row each.
  - Click a column title to sort, click again to reverse. Drag titles to reorder, drag their edges to resize
    (remembered for this library).
  - Grades sort by the value behind them, best first: authority, power and detail from the top of the original's scale
    (... C, B, A, a, b ... s), letter from A, bonus from 1 (tracks without a bonus number go last).
  - The search box keeps only tracks matching every word you type (in any column).
  - Double-click artist, title, album, year, genre, BPM, key or one of your own columns to type a value. Your values
    show in blue. Clear a value to go back to the file's own tag or the estimate. Nothing is written into the audio files.
  - Double-click any other cell for everything about that track.
  - "Add column..." makes a column of your own (numbers or text): streams, sales, chart peak, notes ...
    "Your columns..." renames or removes them.
  - "Import CSV..." fills values in from a spreadsheet saved as CSV. It needs a column called "file" (the track's file
    name, with or without the extension) or "id". Columns named artist, title, album, year, genre, bpm or key, or like one
    of your columns, fill those; any other column becomes a new column of yours.
  - "Remove..." deletes a track's captured data and your values for it (the audio file itself is not touched).

HOW TO READ A GRADE  (also behind the "How to read a grade" button)
  A grade like 30-Abbd reads left to right:
  30-   the number: Chris's "double top 40". Only tracks inside the top 80 get one; 1 is best. No number = outside it.
  A     the letter: how well BALANCED the three meters are with each other. A is best, Z is worst.
  bbd   authority, power, detail: HOW MUCH of each (lows, peaks, highs). Lowercase s ... a = little to plenty, then capitals
        A, B, C ... = exceptionally strong (up to J, or K for detail). Capitals are not a warning.
  What pulls the letter down is one of the three lagging behind the other two. Best possible: 1-AJJK. Worst: Zssv.
  Sorting by Grade follows Chris's order: numbered tracks first (1 to 80), then the rest by letter, A first.

Filters  (Library tab, "Filters...")
  A list of conditions; a track stays in the list only if it passes every line. The grade is filtered part by part, each as its own ranked field:
  - Letter: A is best, Z is worst.      - Authority, Power, Detail: one scale each, ... c, b, a (plenty), then A, B, C ... (exceptionally strong).
    "at least b" means b or better. Capitals count: A is above a. "between" takes two ends, typed like  b to A.
  - Bonus: the number 1-80, 1 is best; tracks outside it have none. "up to 40" means 1 to 40, "between" is typed like  1 to 40.
  Filters saved earlier are converted automatically.

Sample rate
  The sample rate of a file changes what the original Meter reads, even for identical audio (it measures steps between
  samples, so a 96 kHz file looks "smoother" to it than the same audio at 48 kHz). So every track is also read after its
  audio is converted (with a high-quality converter) to 96 kHz, and the Library and the Lab always show those readings,
  with no setting to choose. The meterDARK plugin does the same by default (its "rate" setting in tune is on at 96k), so a
  track reads the same in your 48 kHz session as it does here. A track that has not been rescanned yet shows its readings as
  the file has it until "Rescan library..." has done it. (44.1 kHz readings are also stored, for later.)

Rescan library...  (Add tracks tab)
  Tracks added before the rate readings existed (capture version 1.1) have only the "as file" readings. "Rescan library..."
  reads each of them again from where the file was when you added it and adds the 44.1 and 96 kHz readings. It uses
  several cores, keeps each finished track at once (so you can close the app and carry on later - it picks up the tracks
  not done yet), and shows an estimate of the time left. A track whose file has moved, been deleted or changed is listed in
  the log and left exactly as it is. Your own values are never touched.
  From the command line: meterDARKAnalyserCLI --library <folder> --rescan

Meter versions
  "Grades from" chooses which original Meter's grades the Library shows (the newest by default). "compare with" adds a
  second Grade column from another version, so you can see what a new version changed.
  When the analyser gains a new Meter version, every track is updated for it automatically when you open the app. If that
  version measures the audio differently, the track's audio file is read again from where it was when you added it; a
  track whose file has moved or been deleted says so in the log (add it again to update it).

Directions
  What the original meter's direction line said most of the time during the loud parts of the track, with its share,
  e.g. "allow detail (62%)". The details window also shows what it said at the very end.

Possible duplicates
  Tracks with the same name (ignoring case, the extension and bracketed bits like "(2012 Remaster)") and within 2 s of
  the same length, or with near-identical length, loudness and peaks whatever the name, are shaded red. The red button
  shows only those. Right-click a track (or open its details) and choose "Not a duplicate" to stop it being flagged.

The Library tab (overview)
  Top: the selected track: name, grade, technical details, then a large tone bar (the meter's top colour bar over the track) and three small
    bars under it, all on the same horizontal scale so playback lines up across all four. Rows are named tone / punch / detail.
    Each small bar lights up where that meter is leading the other two:
      Green = tone leads (the tone, the body and low end, carries that section, at the expense of punch and detail).
      Blue = punch leads (the peaks, hits and impact are out in front; it does not mean squashed).
      Red = detail leads (the slews, brightness and fine high detail are out in front).
      White in the big bar with all three small bars dark = balanced: nothing leads.
      A lit bar says "this is what dominates here", not "this is wrong".
    A line under the bars says in words who leads at the playhead or mouse
    ("2:41 punch leads", "punch + detail lead", "balanced").
    "Overlay lines" (off by default) draws, inside each small bar, a line: tone = bass position, punch = peak, detail = slew.
    Play / Stop plays the file from where it was when you added it. Click anywhere on the bars to start playing from that point (or drag to seek while playing); the playhead shows on the big bar.
  Bottom: the list. Default columns: track name, a small tone strip, grade. Right-click the column header to add more columns (artist, album, year,
    BPM, key, LUFS, peak, true peak, length, sample rate, bits, source, format); your choice is remembered. Click a header to sort.
  "Build / update records" makes the small lean record of every track from the window data already stored (no audio is read) and keeps tags and
    source up to date. Records are in the library's lean folder. "Full table" opens the old table.
  "Source" (Tidal, Spotify, Apple Music, Vinyl, CD, HDtracks, Qobuz, Other, or type your own in the full table's Source column) says where a copy came from.
  Copies of the same song (same artist + title, about the same length) are grouped: the list says "(3 versions)", the best one is marked "best"
    (best grade, then higher sample rate), and "Compare versions" stacks their tone bars.
  "Share packs..." exports a display pack (small) or a full pack (adds the replay blocks so others can regrade), or imports a pack. Packs never
    contain file names or paths. Imported tracks show as "(shared)" and are kept apart from your own measurements (lean-shared folder).
  Command line: --lean (build records), --lean-check (rebuild all and prove each replay block regrades to the same grade), --export-pack, --import-pack.

The gradeLAB tab
  The original-scoring experiment (it used to be inside the Lab). "Use replay blocks" regrades from each track's lean record (and from shared
  records that carry a replay block) instead of the stored window data. Nothing here changes the Library's real grades.

The hintLAB tab  (this was called the Lab; its "Original scoring" part will move to a gradeLAB tab later)
  An experiment space. Nothing in it changes the Library's real grades.
  Click a track in the list: its dot in the top strips is drawn big, green if that gauge is inside the balanced zone, red if it would trigger a hint.
  meterDARK hints: the plugin's thin/full, headroom/squashed and dark/bright hints (three gauges; dark/bright is one gauge with a width shade), simulated over your whole library as
    you move the settings. The strip at the top shows where every track's readings sit (dots) against the triggers (lines);
    the table shows each track's average readings and how much of the time each hint would show (yellow = most of it).
    "Set triggers from the library" puts each balance point in the middle of your library and each trigger so that the
    chosen share of tracks lands beyond it. "Export to meterDARK" sends everything to the plugin: the reading settings
    take effect straight away, even while the plugin is open ("hintLAB" shows at the bottom of the meter), and the
    triggers become its default preset for new instances (your old preset is kept as defaults-before-lab.xml).
    When it finishes it lists every setting that differs from factory. If everything is still factory nothing will look
    different. Plugins already open and saved projects keep their own triggers until you press "factory" or
    double-click the setting in the plugin's tune panel.
    Tone (it was called weight) is now THIN <-> FULL: where the loud part of the sound sits in the bass (about 300 Hz = thin, about 60 Hz = full).
    "Measure low end" reads each track's real low-end energy (the 31, 62 and 125 Hz bands, from the stored fine blocks; first run
    takes a few minutes, then it is cached in lowend.csv). The two plots under the strips put real low end across and the tone
    reading up, for the retired "old tone" and the new one, with a correlation number r (1 = follows it perfectly, 0 = unrelated).
    The new one should be clearly higher. Please check this on your library: it could not be tested without your tracks.
  Detail decay and fill gate (in DETAIL, 0 = stock) are meterDARK's two settings for keeping brief bright transients out of
    the Detail readings; they are exported with the rest. In "Original scoring" the same two settings show what they do to
    the grades, as meterDARK does with its "grade" tick on.
  Original scoring (experiment): a copy of the newest original Meter's scoring with its constants as settings. Press
    "Re-score library" (a minute or so) to see which grades change and how the ranking moves. "Save settings..." keeps them
    in a file, for example to show Chris. "redraws per window" above 1 shows what happens when a DAW renders faster than
    the screen redraws, which is why the original's offline scores differ.

Updates
  The app checks GitHub when it starts. If a newer build exists (for example one that adds a new original Meter), a
  yellow button on the Add tracks tab offers the download. Nothing is downloaded until you click it.

BPM and key
  Both are estimated from the audio. BPM can come out at half or double the tempo you would count; key can land on the
  relative major/minor (C major / A minor) or a fifth away. Less certain estimates show grey with a "?". Correct any of
  them by double-clicking: your value wins.

What is in the library
  index.csv                one row per track: tags, format, levels, loudness, and the original meter's grade
                           (opens in Excel)
  tracks\<id>.core-<version>.csv  each original Meter version's own data: one row per 42.7 ms window, exactly the
                           values that version sends to its display (0.5.6 sends twenty)
  grades-<version>.csv     each original Meter version's grade for every track, audio as the file has it
  grades-<version>@44100.csv, @96000.csv   the same after the audio was converted to 44.1 / 96 kHz
  tracks\<id>.core-<newest version>@44100.f32.gz, @96000.f32.gz   the newest version's window data for the converted audio
  tracks\<id>.fine.f32.gz  ~5.8 ms blocks with enough detail to rebuild any longer window, plus extras
                           (RMS, true peak, loudness, stereo, ten octave bands)
  tracks\<id>.pitch.f32.gz how strongly each of the 12 notes sounds, every ~93 ms (used for the key)
  tracks\<id>.meta.json    everything about the file, its tags, and how it was captured
  user.csv                 YOUR values (tag fixes, BPM/key corrections, your columns), kept apart from the measurements
  columns.json             the names and types of your columns
  README.txt               the same, in more detail

  Roughly 1-2 MB per minute of audio.

Sharing it with Claude
  Zip the library folder (or just index.csv for a quick look) and attach it to the chat.

The original meter's grade
  The grade in index.csv is the original Meter's scoring, replayed at text speed exactly as it runs in real time
  at the plugin's default window size (1080 x 720). The original scores in step with the screen redraw, which is
  why rendering faster than real time in a DAW changes its readings; the analyser does not have that problem.

Command line (optional)
  meterDARKAnalyserCLI.exe [--library <folder>] [--rescan] <files or folders...>

For analysis scripts
  mdark_library.py (Python 3 + numpy) reads a library and rebuilds windows of any length from the fine blocks.
